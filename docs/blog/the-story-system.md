# What is the story system?

What I wanted in AppWeaver was a way to walkthrough the app and show the user how to use it. But because we have plugins, I decided to build a system that even plugin authors can use it to document their plugins.

I call this system "stories". Today we have walktroughs that guide the user through the app, but the same system can be used to showcase a specific feature of a plugin or a command. In showcase mode, when you start AppWeaver in `--demo` mode, it is automatically played with a fake cursor clicking through the app. The app state is predefined by the story definition, which at the end fed into the normal app state. This state then used to generate the app UI.

A story is a sequence of steps that are executed in order. Each step is a command that is executed in the app. The steps are executed in order, and the story is complete when all steps are executed.  

The interactive demo app running in https://getappweaver.com is also powered by the same system. There is no backend behind the demo app, and it's just a static website. How does it work? The answer is to generate the app UI from the story definition. The story definition is a JSON file that is stored in the `apps/landing/public/demo/app/demo/stories.json` file. This file is generated by the `demo:generate` command from all the commands and plugins in the app.
